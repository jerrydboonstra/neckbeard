# Gallery

Facts reports on seven public plugins and skill packs, and one fit report that neckbeard ran on itself. A **facts report** lists what a plugin adds to a Claude Code session: the skills and rule text it injects, the hooks it registers, the agents and commands it ships, the files it may write, and the servers it reaches. It has no verdict and no model call, and it never judges whether the plugin is good. Every report here is dated and names the commit it read, so an old one is easy to spot.

## The one fit report

A **fit report** goes further than a facts report: it compares a plugin's rules with the rules you already run, and sorts each one into conflicts, duplicates and new. That needs a reader's own rules, so a fit report is for your own use and is never a plugin's published verdict. [neckbeard.md](neckbeard.md) is neckbeard's fit report on itself, kept here only as a labelled demo of what one looks like. Nothing on this page judges another project's plugin.

The demo ran against a [sample reader](reader/), the "rules already in force" for a fictional developer, laid out the way a real Claude Code config is: a [`CLAUDE.md`](reader/CLAUDE.md) that pulls in [`rules/safety.md`](reader/rules/safety.md) and [`rules/engineering.md`](reader/rules/engineering.md) with `@` imports, and one personal skill, [`skills/release-notes/`](reader/skills/release-notes/SKILL.md). It is small on purpose, so a citation in the report can be checked by eye. A verdict is always relative to the reader it ran against.

To run a fit report against your own rules, see [docs/publish-your-report.md](../docs/publish-your-report.md) (`tools/vet --reader DIR`).

## Reproduce one

Clone the plugin, then run neckbeard's one command on it. It needs only python3 and no login:

```bash
tools/vet <path-to-plugin> report.md --facts
```

The report's header line names the neckbeard version, the plugin's version and its commit. A rerun on the same commit gives the same report apart from the date.

## How these were made

Each facts report is generated by `tools/vet --facts` on a fresh clone of the plugin at the version in the table, and is never edited by hand: a regenerated report replaces the old one, and the excerpts in [README.md](../README.md) and [CASE-STUDIES.md](../CASE-STUDIES.md) are copied from the reports by `tools/excerpts`, so they cannot drift. The case studies keep what each earlier run found, so they show how the reports changed over time.

The maintainer guide for publishing your own report, with the badge and the CI check, is [docs/publish-your-report.md](../docs/publish-your-report.md).
